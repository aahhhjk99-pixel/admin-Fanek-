# FANEK — لوحة الإدارة والموظفين (v1.1)

لوحة React + Vite عربية RTL متصلة بـ Supabase: الزبائن، الفنيون، الخدمات، النزاعات، المالية، الوكلاء، الإعدادات، الموظفون والصلاحيات، وسجل التدقيق.

## 1. إعداد الواجهة

1. استخدم Node.js 20 أو أحدث.
2. انسخ `.env.example` إلى `.env` وضع عنوان المشروع والمفتاح العام (publishable/anon) فقط.
3. شغّل:

```bash
npm install
npm run dev
```

للبناء: `npm run build`.

## 2. إعداد قاعدة البيانات (مرة واحدة)

1. أنشئ حسابك من Authentication ثم شغّل `database/OWNER_BOOTSTRAP.sql` بعد وضع UUID حسابك لتصبح المالك الأساسي.
2. شغّل `database/EXTRA_FUNCTIONS.sql` (عمود must_change_password، دالة تغيير كلمة المرور، دالة إيقاف/تفعيل الحسابات مع تسجيل التدقيق).

## 3. إنشاء حسابات الموظفين من الموقع

صفحة **الموظفون والصلاحيات** تنشئ الحساب عبر Edge Function اسمها `create-staff-user` تتحقق من أن المستدعي المالك الأساسي. انشرها:

```bash
supabase login
supabase link --project-ref pwszxdujmpolnxyoquls
supabase functions deploy create-staff-user
```

لا تضع `service_role` في `.env` ولا في ملفات الواجهة ولا على GitHub.

## 4. النشر

المشروع يستخدم BrowserRouter، لذلك يحتاج الاستضافة إعادة توجيه كل المسارات إلى `index.html`. الملفات جاهزة: `vercel.json` لـ Vercel و`public/_redirects` لـ Netlify. على GitHub Pages لا يعمل التوجيه بدون حل إضافي، فاستخدم Vercel أو Netlify أو Cloudflare Pages.

## 5. ما الجديد في v1.1

- الصفحات والقائمة تظهر حسب صلاحيات الموظف (تحسين للواجهة فقط؛ الحماية الحقيقية في RLS).
- إجبار الموظف الجديد على تغيير كلمة المرور المؤقتة، وصفحة «حسابي» لتغييرها لاحقًا.
- إيقاف/تفعيل حساب الزبون والفني والموظف مع سبب وتسجيل في سجل التدقيق.
- مولّد كلمات مرور قوية عند إنشاء حساب موظف.
- إصلاح محرر JSON في الإعدادات، وتفادي ظهور «الوصول مرفوض» لحظة تسجيل الدخول، وزر خروج في شاشة الرفض.
- DataTable لا يفشل إذا لم يوجد عمود الترتيب في الجدول.

## 6. ملاحظات مهمة

- الحسابات المنشأة لها كلمة مرور مؤقتة؛ سلّم البيانات للموظف عبر قناة خاصة.
- يجب أن يكون حساب المالك في `public.profiles` و`public.admin_permissions` مع `is_super_admin = true`.
- إخفاء عناصر الواجهة ليس حماية أمنية؛ الصلاحيات الفعلية تعتمد على RLS ودوال قاعدة البيانات.
- إيقاف حساب لا يقطع جلسته الحالية فورًا؛ تأكد أن سياسات RLS تفحص `account_status`.
- إنشاء حساب «وكيل شحن» ينشئ ملف المستخدم فقط؛ سجل الوكيل في جدول `agents` يُضاف بشكل منفصل.
- التعويضات والجدولة والإشعارات (FCM) تحتاج إعدادًا واختبارًا مستقلًا قبل الإنتاج.
- لا يمكن ضمان عمل المشروع 100% قبل تشغيل build واختبار الدخول والسياسات على مشروعك.
